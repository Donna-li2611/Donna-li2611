# 作品集结构与维护

个人主页负责导航，四个项目仓库各自保留当前说明与证据。一个成果只在一个仓库维护，其他地方通过链接引用。

| 仓库 | 内容职责 | 下一个证据节点 |
| --- | --- | --- |
| bloom-daily-habit-tracker | 产品案例、核心代码、质量记录 | TestFlight 新构建的真机安装与核心流程记录 |
| health-llm-evaluation | 问题集、评分、采集条件、评测证据 | 完成一次有原始记录和复核的试运行 |
| healthcare-ai-research | 公开事实与分析、研究方法 | 新增一个按相同口径整理的案例 |
| wuxing-spirit | 玩法、交互原型、体验假设 | 完成一轮手机端核心循环观察 |

每次发布后更新项目首页的阶段和证据日期。替代方案留在 Git 历史；影响维护的关键原因保留在决策文档。实际测试数以测试输出为准，计划指标不能写成已实现结果。
